Key 要放在哪里？

放在运行 Agent 的电脑上，不是粘贴到接入文档里。这页告诉你具体放法；本地 Mock 不接收或保存真实 Key，也不检查真实连接。

连接配置

服务地址：https://www.sixnine.art（正式网站）
密钥变量：SIXNINE_API_KEY
作用：让映序 Skill / API 客户端读取网站 Key；不是替换 Codex 自己的模型 Key。

这是现有客户端约定。新的聊天任务卡接口仍未接通。DEMO_NOT_VALID_ 开头的演示值无法使用。

我使用 Codex 桌面应用

先把下面这段发给 Codex，里面没有密钥。Agent 应先查现有凭据配置，缺少时才引导你用本地安全输入；不会让你把 Key 贴到聊天里。

请按映序官方 Skill 配置网站 API 访问：https://www.sixnine.art/for-agents/SKILL.md
目标网站是 https://www.sixnine.art。
先检查这台电脑已有的密钥管理器/中央 API Registry，确认 sixnine profile 的端点和账户，不打印密钥，不自动选其他账户。
如果缺少匹配凭据，请提供本地隐藏输入的配置步骤，将 Key 存入我选定的加密库。不要让我把 Key 发进聊天或写进普通配置文件。
配置完成后，仅报告配置状态；不要生成视频、上传素材或启动 GPU。连接验证另行确认。
当前若来自 Mock 页面，仅讲解配置步骤，不使用演示 Key 调用。

已有加密库时直接复用，不需要再粘贴 Key。尚未实现“一键连接桌面应用”或授权回调；这个原型不会假装已经连接。

我使用 Codex CLI（Windows PowerShell）

  1. 在正式网站创建 Key，复制一次性显示的值。
  2. 打开 PowerShell，复制运行下面的命令。
  3. 出现“请粘贴…”后，再粘贴 Key。这里才是输入位置，字符不会显示。
  4. 命令从同一终端启动 Codex CLI，然后把官方 Skill 链接和创作需求交给它。
# 正式 Key 配置示例；演示 Key 不可用。不写入文件或系统环境。
$previousSixnineKey = $env:SIXNINE_API_KEY
$inputSixnineKey = Read-Host "请粘贴映序网站 API Key（输入不显示）" -AsSecureString
try {
    $env:SIXNINE_API_KEY = [System.Net.NetworkCredential]::new("", $inputSixnineKey).Password
    # 从同一个终端启动 CLI，新进程才会继承这个变量。
    codex
} finally {
    $env:SIXNINE_API_KEY = $previousSixnineKey
    $inputSixnineKey.Dispose()
    Remove-Variable previousSixnineKey,inputSixnineKey -ErrorAction SilentlyContinue
}

需要已安装 Codex CLI。变量只供这个终端启动的子进程继承，不会自动配置已经打开的桌面应用。CLI 退出后恢复原进程变量；这不是长期保存方案，下次需重新配置或使用加密库。

配置后，如何知道成功了？

“变量存在”“加密库能加载”和“网站鉴权成功”分别报告。正式版应提供单独的只读连接检查，显示账户、Key 权限和可访问范围；不以生成视频来检查连接。本 Mock 没有执行这种检查。
