## 用户入口与交互

- 「参考素材」直接拖入文件，或点上传图片 / 视频 / 音频。不必先创建文字节点。素材卡显示实际图片与视频画面；声音有播放器，文件可替换。
- 新建人物 / 地点时可同时上传图片，作为基础造型主图 / 地点参考。角色库保留多造型、多视角图集；地点库可添加、预览、复用多张图片，并绑定场戏。
- 「镜头与参考」先选文生 / 首尾帧或全能参考，再上传对应素材。每次只展开一个镜头，镜头导航有缩略图；分镜文字与拍法收进可选展开区。
- 每个镜头独立保存首帧、尾帧、图片参考、动作视频、音频参考、视频原声开关和时间锚点；视频 / 音频可复用并选择原文件有效片段。
- 人物造型、场戏地点会在全能参考模式中带入真实图片，显式镜头设置可覆盖场戏默认值。图片数量包含这些继承图；达到上限时不能继续上传，异步上传完成前再次核对当前数量。
- 文生 / 首尾帧模式保留故事角色与地点安排，但不发送共享参考图。直接关联的普通参考不会静默删除或忽略，混用仍提示修改。
- 本机镜头页直接编辑完整服务声明的 H3 控制，无需先复制云项目才能看到选项。操作参数不会触发租机。本机草稿和云任务提交明确分开。

## 未在本轮宣称完成的能力

- 人物图集是上传、选择与复用入口；没有新增付费人物图片模型生成服务。
- Marble / 3D 场景生成不在本轮上传 UX 范围；地点图片参考可用，3D 服务不能伪称已集成。
- 实际服务未开放的 schema 选项继续清楚标记，不绕过执行池 / GPU 资格限制。
- 角色和地点的场戏继承当前可用镜头覆盖为另一造型 / 地点；如要在 REF 镜头单独完全排除某个继承角色，将来可增加明确的禁用覆盖状态，不能用空值误代表已经排除。
- 本机素材与服务账户授权是既有体系；跨站登录问题由独立后端修复，不由此 UI 改动降低校验。

## 实践依据

- 原生文件选择器提供明确格式和多选支持，拖放是补充而非唯一入口；`accept` 不代替运行时验证。[MDN 文件输入](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/input/file)
- 输入区、模式、时刻、原声等都有具名 label / region，使用者不需要依靠 placeholder 理解用途。[W3C WAI 表单标签](https://www.w3.org/WAI/tutorials/forms/labels/)

部署建议：先让用户在本机验收人物、地点、两个镜头与参数编辑；用户同意后再按前端范围统一同步 / 发布，不把本批 UI 随 GPU 修复直接上线。
